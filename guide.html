Slide 3 / Step 1 — รับตัวอย่าง
QC SAMPLER qc-entry.html

📥 ลงทะเบียน + ขอเบิก stock

  1. 1
    เปิด qc-entry.html → กด "+ ลงทะเบียนตัวอย่างใหม่"
  2. 2
    กรอกข้อมูลผู้ขอเบิก + วันที่ + วัตถุประสงค์ (Routine / Stability / Customer ฯลฯ)
  3. 3
    เลือก ประเภทแหล่งที่มา เช่น "ใบสั่งผลิต (Work order batch)"
  4. 4
    ⚡ Cascading filter ทำงาน → dropdown สินค้าโชว์เฉพาะ category ที่เกี่ยวข้อง (FG)
  5. 5
    เลือก FG-FIN-003 → เลือก Lot → ระบบ auto-fill: mfg date / exp / storage
ประเภทแหล่งที่มา ─→ กรองสินค้า: ┌─────────────────────────┬──────────────┐ │ ใบสั่งผลิต │ FG-* │ │ วัตถุดิบเข้า │ RM-* + PK-* │ │ ระหว่างการผลิต │ FG-* │ │ ผลิตภัณฑ์สำเร็จรูป │ FG-* │ │ ความคงตัว │ FG-* │ │ สินค้าคืน │ FG-* │ └─────────────────────────┴──────────────┘
Slide 4 / Step 1 (cont) — Test Panel + Sampling
QC SAMPLER

📋 เลือก Test Panel + ยืนยันเบิก

  1. 6
    ระบบโชว์ Test Panel ที่ผูกกับ category ของสินค้าอัตโนมัติ (Appearance, ID, pH, Assay, Microbial...)
  2. 7
    เลือก mode การคำนวณจำนวน sample ของแต่ละ test:
    • USP — ตามมาตรฐาน (default)
    • √n+1 — ตามจำนวน lot
    • Fixed — กำหนดเอง
  3. 8
    ดู "สรุปจำนวนสุ่ม" ที่ sidebar ขวา — รวมทุก test panel + retain sample
  4. 9
    กด "ยืนยันเบิก + ลงทะเบียน" → ระบบสร้าง QC-2026-000011 + ตัด stock
📊 สรุปจำนวนสุ่ม (sidebar)
รวมจาก test ที่เลือก (5 test): 12 ชิ้น เมื่อ retain sample (+ 3 ชิ้น): 20% ต้องเบิกทั้งหมด: 15 ชิ้นตัวอย่าง
Slide 5 / Step 2 — Sampling Plan + Stock
LAB TECH qc-detail.html

🔬 ยืนยัน Sampling + ตัด Stock

  1. 1
    เปิด qc-detail.html ของ sample ที่เพิ่งลงทะเบียน
  2. 2
    เห็น 5-stage progress bar ด้านบน — ปัจจุบันอยู่ ① Registered
  3. 3
    ที่การ์ดซ้าย "Sampling Plan" — ดู method + จำนวน + Multi-stage
  4. 4
    Test panel ทางขวาถูก ล็อค 🔒 — ยังกดทดสอบไม่ได้
  5. 5
    กดปุ่ม "ยืนยันสุ่มตัวอย่าง · ตัด 20 capsules"
  6. 6
    Modal confirm ขึ้น → ระบบสร้าง Stock Movement → กดยืนยัน
  7. 7
    Stock 50,000 → 49,980 · TXN ref ปรากฏ · stage เลื่อน → ② Draft
  8. 8
    Test panel ปลด lock ✓ — เริ่มทดสอบได้
↶ Reversal: ถ้าตอน Draft ยังไม่เข้า In Progress — กดปุ่ม "ยกเลิก sampling · คืน stock" ได้ · เข้า In Progress แล้ว reverse ไม่ได้
Slide 6 / Step 2 (cont) — ทดสอบ + OOS
LAB TECH

🔬 บันทึกผลทุก test

  1. 1
    คลิก test ใน list ซ้าย เช่น "pH Value"
  2. 2
    ดู Specification ทางซ้าย: Method / Range / Equipment / Calibration valid / SOP link
  3. 3
    กรอก Reading ทางขวา → ระบบโชว์ ✓/✕ ทันที (live spec check)
  4. 4
    เลือก Replicate (Run 1/2/3) + Equipment + Analyst + Note (optional)
  5. 5
    กด "Save & Next ▶" → ระบบไป test ถัดไปอัตโนมัติ
  6. 6
    หลัง test แรก → stage เลื่อนจาก ② Draft → ③ In Progress
  7. 7
    ถ้ากรอกค่า นอก spec → OOS modal ขึ้น 3 ตัวเลือก:
    • บันทึก OOS — เปิด CAPA investigation
    • Re-test — ล้างค่า กรอกใหม่ + เหตุผล
    • Discard — ทิ้งค่า ไม่บันทึก
┌─ pH Value · USP <791> ─────────────────────┐ │ │ │ Spec: 6.0 – 7.5 │ │ Reading: [ 6.8 ] pH → ✓ Within range │ │ │ │ Reading: [ 5.5 ] pH → ✕ OOS modal! │ │ │ │ 「บันทึก OOS · Re-test · Discard」 │ └────────────────────────────────────────────┘
Slide 7 / Step 3 — Submit + Release
QA REVIEWER

✅ ส่ง Review → Release lot

  1. 1
    เมื่อทดสอบทุก required test ครบ → ปุ่ม "Submit for Review →" ปรากฏที่ footer
  2. 2
    Lab tech กด Submit → stage เลื่อน ③ In Progress → ④ Approved
  3. 3
    QA reviewer (คนละคน) เข้ามา → ดูผลรวมทุก test + history
  4. 4
    ถ้าทุกอย่าง OK → กดปุ่ม "Release ✓" ที่ footer
  5. 5
    Stage เลื่อน ④ Approved → ⑤ Released · lot พร้อมใช้ขาย
  6. 6
    ระบบออก CoA (Certificate of Analysis) อัตโนมัติ (ในระบบจริง)
●━━━━━●━━━━━●━━━━━●━━━━━● ① ② ③ ④ ⑤ Reg. Draft In. Appr. Released ↑ กด Release
✓ Pass case

⚠ OOS branch

✕ Reject case
Reject lot → กลับ producer / scrap

💡 Tips สำหรับ Dev

  • • ข้อมูลทั้งหมดเก็บใน localStorage
  • • Page transition ใช้ window.location ตรง ๆ ไม่ใช่ SPA
  • • ทุกหน้าใช้ React via CDN (Babel-standalone) — ไม่ต้อง build
  • • Production ระบบจริงควรเปลี่ยนเป็น backend API + DB

📌 Edge Cases ที่ต้อง implement เพิ่ม

  • • OOS workflow — Investigation form + root cause + CAPA tracking
  • • Re-sampling — เมื่อ initial sample ไม่พอ / contaminate
  • • Stability study — เก็บตัวอย่างทดสอบที่ time point ต่าง ๆ (0, 3, 6, 12 เดือน)
  • • e-Signature (21 CFR Part 11) — บังคับ password re-entry ตอน Release
  • • CoA template — generate PDF อัตโนมัติ
  • • Stock reversal audit — log ทุก reversal พร้อม reason
